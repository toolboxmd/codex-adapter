**Findings**

- **P0: v0 scope is too broad to be reliable.** The settled scope says local Claude Code only and current Codex first ([33](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:33), [38](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:38)), but v0 also includes web search, parallel agents, MCP calls, terminal control, filesystem actions, collaboration, fuzzy search, and upgrade automation ([196](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:196), [271](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:271), [278](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:278), [282](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:282), [607](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:607)).  
  **Plan change:** define v0 as setup, diagnostics, context-preview, review/adversarial-review/plan-review, chat/rescue, status/result/cancel, resume/fork, and model/permission diagnostics. Move web-search, parallel agents, MCP calls, terminal/fs public actions, review gate, and upgrade automation to post-v0 or experimental.

- **P0: "local-only" is ambiguous for privacy and trust.** The plan says local binary/app-server only ([34](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:34)), but a local Codex run can still send prompts/files to hosted models or use MCP/network paths. Context packaging has no redaction, gitignored-file, `.env`, secret, binary, or egress policy ([397](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:397)).  
  **Plan change:** add a "data egress and redaction contract": local-only means no remote adapter relay, not offline execution. Persist auth/provider/network mode, redact sensitive inputs, warn in `context-preview`, and require explicit inclusion for secrets, env files, ignored files, and outside-workspace roots.

- **P0: background approval handling is underspecified.** The plan names server-initiated approvals and approval mapping ([162](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:162), [167](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:167)), while profiles use `on-request` for write/network paths ([351](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:351), [361](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:361)), but it never defines how unattended jobs pause, surface approval, time out, or prevent agents from self-approving unsafe actions.  
  **Plan change:** add an approval state machine: `pending_approval`, durable approval artifact, timeout behavior, denial handling, cancel/resume semantics, and a rule that autonomous agents cannot approve their own write/escalation requests unless a profile explicitly permits it.

- **P1: the action inventory contradicts the plugin shape.** Target commands stop at setup/chat/review/rescue/status/result/cancel/resume/fork/diagnostics/models/permissions/MCP/plugins/skills ([110](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:110)), but later v0 names include `exec`, `structured-exec`, `prompt-preview`, `policy-check`, `terminal-*`, `diff`, `mention`, and `codex-subagents` ([243](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:243), [254](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:254), [261](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:261), [322](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:322)).  
  **Plan change:** add a single v0 action matrix with columns for command file, runtime handler, app-server/CLI dependency, permission profile, tests, and status. Anything not in the matrix should not be v0.

- **P1: direct filesystem and terminal actions risk reimplementing Codex instead of adapting it.** The reliability contract says to treat app-server as source of truth and keep the adapter thin ([52](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:52)), but public v0 filesystem and terminal control would make the plugin a second execution UI ([271](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:271), [272](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:272)).  
  **Plan change:** in v0, use fs/command methods only internally for Codex event capture, approvals, and result rendering. Keep public `terminal-*` and direct `fs-*` actions future unless a concrete agent workflow requires them.

- **P1: parallel agents/worktrees are v0 scope creep with unresolved safety defaults.** Parallel agents are in v0 action surface, phase work, and DoD ([199](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:199), [552](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:552), [609](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:609)), but core defaults remain open questions ([582](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:582), [583](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:583)).  
  **Plan change:** demote to v1, or limit v0 to read-only `parallel-review --count 2`. If retained, close count caps, branch naming, dirty-tree handling, submodules/LFS, dependency install policy, cost limits, and crash cleanup before implementation.

- **P1: web-search is promoted to v0 without a capability gate or source contract.** It appears in the action surface, examples, implementation phase, and DoD ([196](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:196), [221](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:221), [546](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:546), [607](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:607)), but there is no probe for whether local Codex actually has web/search available under the current auth/model/network profile.  
  **Plan change:** make it post-v0, or require diagnostics to verify search availability before enabling it. Add a result contract for citations/links and a hard failure mode when search is unavailable.

- **P1: context handoff omits several reliability-critical fields.** Minimum fields cover request, plan, git status, files, exclusions, failures, permissions, stop condition, and output contract ([399](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:399)), but not active `AGENTS.md`/Claude instructions, latest user constraints, dirty worktree ownership, file hashes/sizes/truncation, symlink handling, ignored files, env allowlist, MCP/tool visibility, or schema version.  
  **Plan change:** define a versioned context package schema with provenance, token budget, redaction report, instruction layers, file manifest, and exact output schema.

- **P1: upgrade workflow can silently move the compatibility target.** The plan says move compatibility forward after new releases ([38](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:38)), and regenerate protocol from the installed Codex ([496](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:496)), but does not require a committed baseline schema or versioned capability fixtures per supported release.  
  **Plan change:** pin the v0 baseline release, commit generated bindings/capability snapshots, gate each action by required methods, and test baseline plus latest. New Codex versions should be admitted only after compatibility fixtures and smoke expectations are updated.

- **P2: Claude plugin packaging is under-specified.** The tree includes `.claude-plugin/plugin.json` and commands/hooks/skills ([104](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:104)), but there is no local install contract, command namespace, plugin data path, Node engine, executable permission strategy, schema validation, or clean-profile load test.  
  **Plan change:** add a packaging section for local install/update/uninstall, state directory location, command names such as `/codex-adapter:review`, manifest validation, and a smoke test that Claude Code loads commands, agents, skills, and hooks.

- **P2: path-resolution guidance contradicts itself.** Slash commands are told to invoke `node "${CLAUDE_PLUGIN_ROOT}/scripts/codexctl.mjs"` ([178](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:178)), while later guidance says not to rely on `${CLAUDE_PLUGIN_ROOT}` inside Bash-tool instructions ([466](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:466)).  
  **Plan change:** choose one sanctioned path mechanism and document it. Prefer a manifest/config-time absolute script path plus script-relative resolution internally.

- **P2: DoD lacks failure-path acceptance criteria.** Reliability requires actionable failures for install/auth/config/app-server/sandbox/rate-limit/MCP/job interruption ([59](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:59)), but v0 DoD mostly covers happy-path workflows ([603](/Users/lukaszmaj/dev/toolboxmd/codex-plugin-cc-enhanced/rewrite-codex-cc-plan.md:603)).  
  **Plan change:** add DoD items for broken install, expired auth, app-server busy/crash, missing method, rate-limit depletion, approval denied/timeout, sandbox denial, MCP unavailable, malformed event, cancellation race, and stale broker recovery.

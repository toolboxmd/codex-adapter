**Final MVP Taxonomy**
- Core: `setup`, `diagnostics`, `context-preview`, `status`, `result`, `cancel`, `execute`, `review`, `rescue`.
- Gated v0: `search`, `compare`, `execute` with structured output.
- Post-v0: `resume`, `fork`, `models`, `permissions`, `config-debug`, `upgrade-check`, `mcp`, `plugins`, `skills`, `features-list`, `apps-list`, write-capable `parallel-agents`, worktree orchestration, review-gate automation.

**Intent Router**
- `execute`: Claude expresses `execute` with `mode=chat|exec`. Plugin chooses `turn/start` vs `codex exec`, a task package, explicit permission profile, foreground/background behavior, and returns final answer plus commands/files/result artifact paths.
- `review`: Claude expresses `review` with `mode=code|plan|adversarial`. Plugin chooses native `review/start` when possible, otherwise a review turn, uses a review package, forces read-only, defaults to background for non-trivial scope, and returns findings-first output with file refs and suggested next action.
- `rescue`: Claude expresses `rescue` with a failure target and stop condition. Plugin chooses a diagnostic turn first, escalates to write only if explicitly allowed, uses a failure-focused package, runs durably in background, and returns diagnosis, attempted fixes, touched files, and verification state.
- `search`: Claude expresses `search` with a question, recency, and source requirement. Plugin verifies search capability, uses a minimal facts package, keeps read-only/network-gated behavior, and returns dated findings with sources or an explicit gated-unavailable result.
- `compare`: Claude expresses `compare` with a target and rubric. Plugin fans out 2-3 read-only review jobs, uses the same review package for each branch, applies runtime/cost caps, and returns a deduped comparison report with consensus, disagreements, and merged findings.

The main cut I would ship is: keep the public/semantic surface to `execute`, `review`, `rescue`, `search`, and `compare`, plus the operational controls `setup`, `diagnostics`, `context-preview`, `status`, `result`, and `cancel`. Everything else should either be internal plumbing or post-v0 admin surface.
